# Marquee and Gallery functionality: shipped APK evidence

Target: `5D-Holo-android.apk`, package `com.sp.holographic`, version 1.0.85 (105). APK SHA-256 `8a83b1f128beb43341eefd2b4ad743512d0193ff6dd4e7b56feba138fb4b63c9`; Hermes96 bundle SHA-256 `8389750af87d60e75bbd7d93ba57d1bd239008812c8c5ef7ecc84cf2a46777e2`.

This report follows function bodies and actual bytecode calls from the feature pages to their renderers/export helpers. Names and strings were discovery seeds. Curated original disassembly is in [marquee-gallery-bytecode.hasm](marquee-gallery-bytecode.hasm); [marquee-gallery-index.json](marquee-gallery-index.json) records each function's original bundle offset, byte count and SHA-256 of those exact bytecode bytes. [marquee-gallery-strings.json](marquee-gallery-strings.json) retains exact packed renderer/command strings with physical offsets and hashes. Existing `analysis/android/bundle.pseudo.js` provided readable scaffolding; original HASM resolves its occasional incorrect register/call reconstruction.

## Marquee

Observed static implementation: editable colored text repeats horizontally across the middle of a square black Canvas. It is a flat text animation, rather than a special on-device text protocol.

- Module 1477 `DesignMarqueeTextPage`, function **17578**, bundle offset **0x37bc53**, initializes color `#25fc11`, localized `strings('hey')`, and font size **42**. State calls and stores appear at relative offsets `0xad..0x159`. The page gives renderer props `text`, `color`, and `fontSize` at `0x3ac..0x3e4`. It clamps invalid/small font input to **10**, and caps large values at **120**. The size Input has `maxLength:3`, numeric keyboard, and function **17617** (`0x37d56d`) uses `parseFloat`, substituting 0 for NaN. Clearing size restores 42 (17616). Text clearing and `onChangeText` feed the text state (17614/17615). Function **17612** (`0x37cdae`) stores the color-picker result and marks edited state.
- Renderer module 1478, function **17625**, **0x37d6f9**, uses `text || 'Hello'`, `color || '#25fc11'`, `fontSize || 42`, clamps font to 10..120, then JSON-stringifies text/color before inserting them into the HTML. Its authoritative packed HTML pieces are string IDs **555, 2065, 2219, 9488**, loaded at relative `0xa4..0xb0`; `Call` at `0xb7` assembles them. [marquee-gallery-marquee.html](marquee-gallery-marquee.html) is that exact string assembly instantiated with `Hello`, `#25fc11`, and `42`.
- In string 9488, `S=min(innerWidth,innerHeight)` determines square display size; backing Canvas uses device-pixel ratio. `ctx.measureText(TEXT).width` gives text width. `segmentWidth=textWidth+60`, preview `stepSize=segmentWidth/200`, and `speed=segmentWidth/10000` pixels/ms. Each render clears to black and draws repeated copies at `x=-(offsetX % segmentWidth)`, then increments x by segment width. `offsetX += speed*dt` makes the text move left and the preview repeat its phase every **10 seconds**.
- Export pauses animation, resets offset, creates an independent **720×720** Canvas, scales font/gap by `720/S`, and computes `eStep=max(1,round(eSegW/200))`. It advances before drawing each frame. **200** JPEG frames at quality **0.9** leave the WebView in **10-frame batches**, as messages `{t:'b',f:[{i,d}]}`; completion is `{t:'d',n:totalSteps}`; errors are `{t:'e',m}`. Integer rounding means the exported phase need not complete exactly one cycle. Reproduction should preserve this if matching the APK precisely.
- Function **17634**, **0x37d991**, injects `exportFrames(200);true;`; **17635**, **0x37d9f4**, dispatches batch callbacks, resolves once on completion, and rejects on an error message. Function **17637** rejects after **60,000 ms** with `Error('timeout')`. The renderer exposes pause/resume/step and `getTotalSteps()` returns 200. `reloadWebView()` is an empty function (17627).
- Page export button **17620** (`0x37d5ea`) calls compose state slot 13, whose generator **17607** (`0x37cb1b`) calls `MediaUtil.generateVideoFromWebGL(ref, callback)`. Success/failure goes to handleSaveVideo **17579**. Shared video encoding is covered by the main investigation. At 20 fps, these 200 frames represent **10 seconds**; this is an inference combining this renderer's frame count and shared encoder rate.

Offline corroboration: [marquee-gallery-browser-replay.json](marquee-gallery-browser-replay.json) records actual desktop Chrome Canvas/JPEG execution of the exact assembled HTML: 200 frames, indices 0..199, done message `n:200`, and both sampled JPEGs decode as 720×720 with thousands of nonblack pixels. The local native bridge was mocked; no Android app, device conversion, network upload, or phone font measurement occurred. [Browser probe](marquee-gallery-browser-probe.html) and [runner](marquee-gallery-browser-replay.py) reproduce it. The additional [mock Canvas replay](marquee-gallery-replay.json) checks batching and algebra with explicitly synthetic text metrics; its JPEG bytes are placeholders and are not image evidence.

## Gallery

Observed static implementation: six selectable photo slots with animated sample-picture preview. Export uses a different transition from that preview.

- Module 1480 `DesignGalleryPage`, function **17694**, **0x37f5b6**, initializes **six empty strings**, constructs sample images from dependency slots 13..18, and passes a six-item looping carousel `autoPlay:true`, `autoPlayInterval:1000`, `scrollAnimationDuration:500`. Carousel dimensions are `0.9*deviceWidth` by `3/4` of that width, within a square captured parent View.
- Module dependencies 1642..1647 register sample assets `purple-0` through `purple-5`, declared PNG **1721×1721**, in functions **18651..18656**. The APK minifies Android resources, so these declarations establish asset references; a filename search alone does not map them to concrete `res/*.png` members. Function **17740**, **0x380bc7**, chooses a picked file URI when the slot is nonempty, otherwise its corresponding sample asset, then uses `resizeMode:'cover'`.
- Preview animation function **17715**, **0x38044f**, calls `interpolate` three times: value `[-1,0,1]` → zIndex `[10,20,30]`, scale `[1.25,1,0.25]`; value `[-0.75,0,1]` → opacity `[0,1,0]`. The exact shipped worklet `function design_galleryJs1(value){...}` is also retained in strings JSON. This explains the overlapping scale/fade preview rather than proving the exported transition is identical.
- `selectImage`, function **17727**, **0x380739**, calls `openPicker({mediaType:'photo',cropping:true,width:800,height:600,...colors})`. Successful result's `path` replaces the selected slot; picker errors are logged. `removeImage` **17733**, **0x380952**, resets the slot to `''`. The page normally holds six slots; if state somehow exceeds six entries, selectImage first truncates to indices `<6`.
- Save/export button **17739** calls compose generator **17722**, **0x3805c5**. It filters picked paths with predicate `path && path.length>0`. With **zero selected photos**, relative `0x76..0xa2` calls **generateStaticVideo(carouselRef,10,callback)**: it records a 10-second still snapshot of the current sample preview, not the sample animation. With **one or more selected photos**, `0xab..0xd3` calls **generateGalleryVideo(filteredPaths,10,callback)**. Empty-slot sample assets disappear from this path. It does not capture the React Native carousel animation in this case.

`generateGalleryVideo` body **8366**, **0x2912bb**, is the export evidence:

1. Creates a temporary cache folder and random `.mp4` output; filters empty paths again. With `n` picked files and requested total `T=10`, relative **0x149..0x174** loads transition **d=0.5**, computes `seg=T/n + d*(n-1)/n`. This is actual `Div/Sub/Mul/Div/Add` instruction math, not an estimate from menu strings.
2. For each image, constructs and executes FFmpegKit command:

   ```text
   -loop 1 -i "IMAGE" -c:v libx264 -preset ultrafast -crf 23 -t SEG -r 20 -vf "scale=720:720:force_original_aspect_ratio=decrease,pad=720:720:(ow-iw)/2:(oh-ih)/2:black" -pix_fmt yuv420p TEMPSEG
   ```

   The literal fragments are loaded near relative `0x17c..0x18c`. Return code `isValueSuccess()` gates pushing each generated segment (relative `0x227..0x23f`). It retains successful segments and can silently omit a failed source image.
3. If there are no successful segments, callback receives `(false,'')`. If exactly one succeeds, the temporary segment moves directly to final output, temporary directory is removed, and callback receives success. If multiple succeed, each transition uses `xfade=transition=smoothdown:duration=0.5:offset=...`. Function relative **0x2c7..0x342** computes transition offset `i*(seg-d)` and serializes it using `toFixed(2)`, chaining `[0][1]... [v1][2]... [vout]`. It maps `[vout]`, reencodes libx264 ultrafast/crf23/yuv420p, then checks return status and cleans up.
4. Ideally `n*seg-(n-1)*d=T=10` seconds when every image succeeds; duration/frame quantization and two-decimal offsets can alter exact output. For three images, `seg=3.666666...` and offsets **3.17, 6.33**. Failed segments use duration computed with the original count, so the actual successful output can be shorter. [marquee-gallery-replay.json](marquee-gallery-replay.json) includes algebra for counts 1..6; it does not claim FFmpeg execution.

There is no explicit audio input or audio mapping in the retained Gallery export commands. No device model/LED-geometry branch appears in the page, renderer, or Gallery generation paths examined; downstream conversion chooses the display format. Neither feature establishes new device types.

## Limits and outcome

Marquee controls, rendered motion, WebView frame protocol, and Gallery selection/preview/export logic are established from exact shipped bytes and call/math instructions. Marquee's standalone Canvas export was additionally executed locally with real JPEG encoding. The installed Android app's UI, native picker behavior, on-device WebView appearance, and Gallery FFmpeg success were not observed. Shared converter/upload/native boundaries remain the main report's scope.
